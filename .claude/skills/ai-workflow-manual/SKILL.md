## 0 · 무엇이 원본인가

```
원본   그 기능의 스킬      .claude/skills/<스킬>/SKILL.md      ← 고치는 곳은 여기뿐이다
도구   10_Ai/10_업무매뉴얼/system_도구/기능장뽑기.py            짝 표(스킬 ↔ 장 파일) · 안넣는스킬(메뉴에 안 넣는 스킬과 까닭)
메뉴   10_Ai/10_업무매뉴얼/목록.js 의 「AI 작업 흐름」 가지        장 맨 위 제목은 여기 적힌 메뉴 이름이다
장     10_Ai/10_업무매뉴얼/8_AI_작업_흐름/<장>.html             도구가 통째로 덮어쓴다 — 손으로 고치지 않는다
```

스킬의 `# 제목 — 큰 흐름` 줄에서 「—」 뒤가 장 제목 옆 부제가 되고, `## ` 줄마다 절 하나가 된다.
스킬 머리의 `> ★ 이 파일이 **원본**이다 …` 덩이는 스킬을 고치는 이에게 쓴 말이라 장에는 안 싣는다(2026-10-03 사용자 Q11 ① · 도구ㆍ원본 말이 없는 뒤 줄은 남긴다) — 스킬에는 그대로 둔다(`--재기` 가 그 덩이를 잰다).
절 제목에 「연계 규약ㆍ함정ㆍ잣대ㆍ인용 꼴ㆍ값을 치르고ㆍ옛 길」 이 들면 그 절은 접힌다 — 큰 흐름ㆍ정한 것ㆍ정할 것만 펼친다.

## 1 · 차례 — 일감 넷

```

                                   ② 목록.js 「AI 작업 흐름」 가지에 한 줄  (이름 = 장 제목이 된다)
                                   ③ 그 스킬 머리에 「이 파일이 원본이다 · 고치면 --만 <스킬> 로 다시 뽑는다」 덩이
                                   ④ python 10_Ai/10_업무매뉴얼/system_도구/기능장뽑기.py --만 <스킬>
```

- 다른 권에 뽑는 장도 있다(다섯 칸 짝) — 「Revit 작성 메뉴얼 › 스캔본 캐드도면화」(원본 `drawing-analysis`). 그 장의 내용은 캐드 일감이 정한다.

## 2 · 함정 — 스킬 글이 장에서 깨지는 자리

스킬은 깃허브 꼴로 쓰는데 도구가 쓰는 변환기(python-markdown)는 다르게 읽는다. 도구가 살려 주는 것과 못 살리는 것 :

- 살려 준다 — 절 제목의 `<sub>`ㆍ`**굵게**`ㆍ백틱 · 문단 바로 아래 붙여 쓴 「- 」 목록 · 두 칸 들여 쓴 속 목록 · 줄마다 적은 인용(「> 」 뒤 한 칸이면 새 줄) · ⚠ ★ ⇒ ※ 와 ① ⑴ ㉮ 로 시작하는 이어 쓴 줄 · `~~지운 글~~` · 백틱 밖 영문 꺾쇠 자리표 · 네 칸 들여 쓴 줄로 시작하는 절ㆍ머리 · 기울임으로 옮긴 사용자 말 `*"…"*` 안의 `**굵게**`(여러 줄이어도) · 울타리 상자 안의 `## ` 줄(절을 안 가른다) · 스킬 폴더 기준 상대 고리(장 자리 기준으로 다시 잡는다) · `## 9 · 지적사항` 절(맨 끝 9절에만 한 번) (뒤 넷은 2026-10-03 아침).
- 못 살린다 — 대괄호 바로 뒤에 소괄호를 붙이면 **고리**가 되어 소괄호 안 글이 사라진다(`[별표](254 줄)` → 한 칸 띄운다) · 문단에 붙여 쓴 **표**는 표가 안 된다(표 앞에 빈 줄) · 표 칸 안의 맨 세로줄은 뒤 칸을 버린다(백틱 안에) · 인용 바로 아래 빈 줄 없이 쓴 글은 인용 상자 안으로 들어간다 · 번호 목록(「1. 」)은 앞에 빈 줄이 있어야 한다 · `## ` 절이 여덟을 넘으면 도구가 붙이는 「8. 고친 이력」 과 번호가 겹친다(그 절은 번호 없이 단다).
- ★글이 사라졌는지는 **낱말 수**로 잰다 — 「그 낱말이 장 어딘가에 있나」 로 재면 같은 낱말이 다른 자리에 있을 때 통과한다(2026-10-02 용도변경 장의 `<YYMMDD>` 한 낱말).

## 3 · 「사용자가 정한 것」 표를 쓰는 법

꼴은 `| 날 | 정한 것 | 담긴 곳 |` 이고 스킬 끝쪽의 절 「사용자가 정한 것 — 고쳐 온 차례 (새로 정하면 여기에 한 줄)」 에 둔다.

- 「…」 안에는 **기록에 있는 사용자 말만 글자 그대로** 넣는다. 지어 넣지 않는다 · 줄여서 뜻을 바꾸지 않는다.
- 한 줄 안에서 **하신 말 / 고르신 답(Q 번호 · 권장대로) / 그 말을 받아 AI 가 고른 방법**을 갈라 쓴다.
  2026-10-03 에 다섯 표를 따로 검토시키니 47건이 나왔다 — 구절은 다 맞았는데 AI 가 세운 규칙이 사용자가 정한 것처럼 실린 곳이 3, 한 대지ㆍ한 줄에 대한 말을 일반 규칙처럼 쓴 곳이 12 였다.
- 답 전(⏸)ㆍ보류(「아직 모른다」)ㆍ옛 길ㆍ뒤에 바뀐 것은 그렇다고 밝힌다.
- ★**Q 번호와 날짜는 구절 맞대기로 못 잡는다** — 「담긴 곳」 을 열어 그 자리의 Q 번호ㆍ날짜와 하나씩 맞춘다. Q1ㆍQ4 같은 번호는 날마다 새로 매겨져 수로 세면 늘 「있다」 가 나온다. 2026-10-03 이 스킬 5절의 두 줄이 구절 7 / 7 이 맞은 채 틀려 있었다(네 결정을 둘로 뭉침 · 처음 정한 날을 다시 정한 날로 적음).
- 「담긴 곳」 의 길은 뿌리부터 적는다(줄여 적으면 `가이드검사.py` 가 「없는 자리」 로 짚는다).
- ★**표를 사람에게 줄마다 O/X 로 넘기지 않는다** — 근거 맞대기는 AI 가 끝내고(`정한것표_근거화면.py`), 사람에게는 판단이 필요한 몇 줄만 §2 물음으로 묻는다. 2026-10-03 표 99줄 근거 화면을 드리고 「틀린 줄을 짚어 주세요」 했다가 *"이거 보고있는데 뭘 봐야하는지도 모르겠다"* 를 들었다 → 「그냥 권장하는대로 해줘 · 나중에 실무를 실제로 보면서 하나씩 따져가면서 봐볼께」(`00_길잡이/가독성_기준.md` 「앞뒤 보기」 마지막 줄).

## 4 · 잣대 — 고쳤으면 돌린다

```
python 10_Ai/10_업무매뉴얼/system_도구/기능장뽑기.py --재기      끝 코드 0 이어야 끝이다
    기능 장 N · 낡은 장 0                    스킬을 고치고 안 뽑은 장
    스킬 N = 장이 있는 스킬 + 안 넣는 스킬 (사용자가 본 것 · AI 가 추려 사용자가 못 본 것) + 안 가른 스킬 0
                                             새 스킬이 생기면 「안 가른 스킬」 → 메뉴에 넣을지 사용자에게 묻는다
    이 권의 장 N · 메뉴에 없는 장 0 · 머리에 원본 덩이가 없는 스킬 0
    글 보존 — 장에 모자란 낱말이 있는 장 0 · 표가 덜 나온 장 0
python 10_Ai/10_업무매뉴얼/system_도구/기능장뽑기.py --자가검사  (2026-10-03 아침 54 가지 · 고침마다 하나씩 꺼 보면 그 케이스 하나가 잡는다)
python 가이드검사.py                                            ⒅ 모든 스킬이 어느 지도에 이어졌나 · 탈 수가 안 늘었나
```

화면은 장을 한 장 찍어 본다(메뉴의 이 권 장 수 · 제목 · 새로 넣은 절). 매뉴얼 서버가 꺼져 있으면 켜지 않고 장 파일을 바로 연다 — 메뉴ㆍ제목ㆍ접힌 절ㆍ글 상자 넘침이 다 나온다(서버는 댓글을 받을 때만 묻고 켠다).
