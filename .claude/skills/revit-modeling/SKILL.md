# Revit MCP 모델링 스킬

> 상위 : `revit-map`
> 앞 : `revit-control` 로 붙은 Revit · 넣을 값
> 다음 : — (끝)
> 넘기는 것 : Revit 요소ㆍ주석ㆍ뷰 · 작업일지

## ★★ 검증 안 된 작업방식이면 매뉴얼을 먼저 검색한다 (2026-08-21 사용자 방침)

> *"revit관련 작업에서 작업방식이 검증되지 않은 작업을 할때는 항상 메뉴얼을 검색해보는 방침을 넣어줘"*

**「검증됨」의 정의 — 이 셋 중 하나에 적혀 있으면 검증된 것이다.**

```
10_Ai/9_Revit/system_표준\ 의 표준문서 (01~05)
10_Ai/9_Revit/system_표준\00_작업일지.md   [성공] 또는 [확정] 태그로 기록된 것
이 스킬 문서
```

셋 다에 없으면 **검증되지 않은 방식이다. 코드를 돌리기 전에 매뉴얼을 검색한다.**
⚠ **이 문서가 다루는 요소 = 그리드·치수·기둥·벽·보·문/창·바닥·기초·계단·난간·텍스트/태그·뷰·패밀리·공정·룸·주석(지시선·문자·태그).**
여기 없는 것(**면적(Area)**, 천장, 지붕, 커튼월, 매스, 대지/지형, MEP)은 **그 자체로 미검증 영역**이다 —
첫 코드를 돌리기 전에 매뉴얼부터 검색한다.

```bash
cd "10_Ai/9_Revit/system_가이드/Revit2021_매뉴얼"
python revit_help.py "family parameter formula"        # FTS5 순위검색
python revit_help.py --book Revit-API "SetFailuresPreprocessor"
python revit_help.py --show GUID-XXXX                  # 본문 전체
python revit_help.py --toc Revit-API                   # 책 목차
python revit_help.py --books                           # 책 목록
```
Revit 2021 도움말 전체 5,089토픽이 로컬에 있다(`books/`·`api/pages/` 의 `.md` 를 Grep 해도 된다).
**패밀리 작업이면 `10_Ai/9_Revit/system_표준/04_패밀리 작업매뉴얼.md` 의 「매뉴얼 지도」 표를 먼저 본다** —
어느 토픽을 볼지 이미 정리돼 있어 검색을 건너뛸 수 있다.

### 반드시 검색해야 하는 3가지 신호

| 신호 | 예 |
|---|---|
| ① **처음 쓰는 API·기능** | `NewSymbolicCurve` 를 처음 쓴다 |
| ② **결과가 예상과 다르다** | 잠갔는데 안 따라온다 / 부호가 반대로 읽힌다 |
| ③ **★ "안 된다"고 단정하려 할 때** | 「API로 불가능하다」고 적기 **직전** |

★ **③이 제일 비쌌다.** 「안 된다」고 일지에 적어둔 것이 실제로 두 번 매뉴얼에 있었다.
```
모달 경고창이 MCP를 멈춘다      -> IFailuresPreprocessor  (Handling Failures)
바닥 개구부는 API로 못 뚫는다   -> NewOpening             (Creating elements in families)
```
⇒ **"불가능"은 검색 후에만 쓸 수 있는 단어다.**

⚠ 매뉴얼 DB의 한계 — 코드샘플이 `<` 에서 잘려 있고(Autodesk 발행 버그), **클래스·메서드
시그니처는 없다**(개발자 *가이드*지 레퍼런스가 아니다). 시그니처가 의심되면 리플렉션
(`t.GetMethods()`)으로 실제 오버로드를 뜨는 게 제일 빠르다.
⚠ `grep -rl` 을 토픽마다 반복하면 42MB를 매번 훑어 **2분 타임아웃에 걸린다.** 여러 개를
확인할 땐 `sqlite3` 로 `revit2021_help.db` 의 `topics` 테이블을 한 번에 조회한다.

## 요소 위치를 어떻게 정할지: 실측자료 vs CAD 도면만 있는 경우

- **정확한 참조 데이터(실측값, 신뢰 가능한 기존 모델 등)가 있으면** → "5. 실측자료 기반 패밀리 유형 검색/생성" 절차를 따른다 (좌표+치수 그대로, 정확매칭 원칙).
- **CAD 선(수기로 그린 이중선 등)만 있고 정밀 참조 데이터가 없으면** → 벽처럼 이미 그리드가 확정된 요소는 **그리드선을 그대로 중심선으로 사용**한다. CAD의 이중선을 정밀하게 페어링해서 별도 중심선을 계산하려 하지 말 것 — 오차와 복잡도만 늘어난다. 두께는 별다른 근거가 없으면 RC 기준 **200mm를 기본값**으로 쓴다 (사용자 확정 규칙).
- CAD 흔적이 그리드에서 일정 허용치(예: 300mm) 이상 벗어나면 **자동으로 만들지 말고 목록만 보고**한다 — 사람이 직접 검토/수정할 대상이다. 억지로 스냅하거나 억지로 정밀좌표를 추정하지 않는다.

### ⚠ 벽에 문/창 자리를 미리 비워두지 말 것

CAD에 문 위치가 보인다고 해서 그 구간만큼 벽을 끊어서(개구부를 미리 뚫어서) 만들면 안 된다. **벽은 개구부 없이 통짜(연속)로 그리고, 문/창은 그 위에 호스팅되는 패밀리 인스턴스로 배치**한다 — 문 패밀리가 배치되는 순간 자신이 필요한 만큼 벽에 구멍을 자동으로 뚫는다. 벽을 미리 끊어서 만들면 문을 얹을 호스트 벽이 끊긴 두 조각으로 나뉘어 오히려 문 배치가 꼬인다. (Revit 자동 벽조인이 끊어둔 구간을 다시 이어붙이는 걸 보고 "문제"라고 착각하지 말 것 — 오히려 정상 방향이다.)

## 절대 하지 말 것: `revit_exec` 안에서 `def` 사용

```python
# ❌ 이렇게 하면 NameError 남
def convert(x, y):
    return (x + OFFSET_X) * MM_TO_FEET, ...
```

**⚠ `lambda`도 똑같이 터진다.** `min(GX, key=lambda g: abs(g[1]-cx))` 처럼 바깥 변수를 참조하는 lambda를 `min`/`max`/`sorted`의 `key`로 넘기면 `NameError: name 'cx' is not defined`가 난다(2026-08-20 실제 발생). 최소/최대 찾기는 for문으로 풀어 쓰고, 정렬은 미리 만든 튜플 순서에 의존하거나 key 없이 `sort()`를 쓴다.

`revit_exec`는 `exec(code, globals, locals)` 구조로 실행되는데, 이때 globals와 locals가 분리된 두 dict라서 함수 내부에서 바깥의 "전역처럼 보이는" 변수를 못 찾는 스코프 버그가 발생한다. **좌표 변환 등은 매번 인라인 계산으로 처리**하고, 반복 로직은 for/while 루프로 풀어 쓴다.

### ★ 그래도 `def` 를 써야 할 때 — `globals()` 로 끌어올린다 (2026-08-31 확립)

조회 코드가 길어지면 함수 없이는 못 쓴다. **함수를 정의하기 전에** 쓸 이름을 전부 globals 에 박는다.

```python
d = [x for x in uiapp.Application.Documents if x.Title.startswith(u'수서동725')][0]
view = ...
for _k in ("DB", "d", "MM", "FT", "view", "sym"):
    globals()[_k] = eval(_k)          # ★ def 보다 먼저. 하나라도 빠지면 그 이름에서 NameError
def bb(e): ...
globals()["bb"] = bb                  # ★ 함수끼리 서로 부를 때는 함수도 올린다
```
⚠ **하루에 세 번 걸린 자리다.** 증상은 늘 `NameError: name 'XXX' is not defined` 이고,
   빠뜨린 이름이 그대로 찍힌다. 트랜잭션 안에서 터지면 롤백되므로 **부분 반영은 안 되지만**,
   `t.Commit()` 뒤에서 터지면 **커밋은 이미 끝난 상태**다 — 예외 위치를 보고 판단할 것.
