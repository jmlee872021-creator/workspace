# 법과 기준 지도 — 찾기 → 없으면 받기 → DB 짓기

> 📄 사용자 (2026-09-17) : *"스킬들이 중구난방으로 분류되어있는거 같은데 스킬들을 잘 분류해야되는거 같아"* → Q1 ① 일감 다섯 묶음마다 지도 하나

**이 스킬은 얇게 둔다.** 절차ㆍ함정은 하위 스킬에 있다. 축은 하나 — *"분석하지 않고 원문을 그대로 인용"*.

## 1 · 일감별 차례

```
가. 조문ㆍ별표ㆍ위임ㆍ조례를 묻는다     law-lookup → 창고에 없으면 law-download → 받은 뒤 DB 에 넣으려면 law-db
나. 조례 별표(hwp 첨부)                law-download (서식받기.py) → hwp5html 로 읽는다 — 법.db 에는 본문이 없다
다. 구조(KDS 41 · 계산서 검토)          structure-kds (기준.db + 법.db)
라. 산업안전(KOSHA GUIDE)               safety-kosha (kosha.db + 법.db)
마. 대지 법률검토(분석02 · Q 로 쌓기)     law-site-qna — 조문은 law-lookup 의 찾기.py · 넣기는 문답넣기.py
마-나. 한국건축규정 250 체크(분석06)   korea-building-code — 관문(걸리나) → 체크항목(맞나) 두 단 · 매뉴얼 권 9 도 같은 정본에서 뽑는다
마-다. 장애인편의시설(BF · 분석02)      accessibility-facilities — **판(version)부터** 고른다 · 별표1 대상 → 별표2 의무ㆍ권장
마-라. 용도변경 검토(분석08)            site-use-change — 의뢰 ↔ 대장 → 매뉴얼 「용도변경 검토」 체크리스트 → 검토서(1쪽 결론) (2026-09-23)
마-마. 해체계획서 변경 검토             demolition-plan-change — 이미 낸 해체계획서를 고쳐야 할 때 「어디를 어떻게」 (건축물관리법 영 제21조의2① · KOSHA C-47 · 2026-09-28)
바-가. 건축행정절차(매뉴얼 권 2 · 49장)   admin-procedure — 일의 순서를 **걸음마다 한 절**로 (정본 yaml → 교재장.py · 2026-09-26 옮김 끝 - 장 html 은 손으로 안 고친다)
바-나. 건축도서 작성메뉴얼(권 3 · 15장)   design-doc-manual — 도서를 그리는 순서 13걸음 (정본 yaml → 걸음장.py)
바-다. 요소별 설계기준(권 13 · 항목 91)   element-design-criteria — 요소 하나(복도 · 계단 …)에 걸리는 법을 모두 겹쳐 예/아니오 나무로 거르고 하한을 정한다 (정본 yaml → 요소장.py · 판단 로직은 마-나ㆍ마-라 와 맞춘다)
바. 「○○는 구조적으로 왜 있나」 · 시공 원리 장  construction-principles — 기준 원문은 structure-kds 로 찾고, 매뉴얼 권 「건축 시공 원리」의 장을 정본 yaml → 원리장.py 로 뽑는다
```
캐드ㆍ대지 쪽에서 법을 부를 때 — `cad-site-review` B장(대지안의 공지ㆍ용도 세 겹) · `site-report`(보고서 용도 검토 절)가 이 묶음의 산출물을 쓴다.
창고 쓰는법(스킬이 아닌 것) — 국가건설기준 `10_Ai/4_국가건설기준센터/쓰는법.md`.
(장애인편의시설ㆍ한국건축규정은 2026-09-21 에 **스킬이 생겼다** — 스킬은 차례 한 장이고, 긴 절차는 그 창고의 `쓰는법.md` 에 그대로 둔다)
