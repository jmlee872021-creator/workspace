## ★ 2026-09-07 — **`--두루` 가 198배 빨라졌고, 그전 답은 틀렸다**

`--두루 "신축이 아닌 기존시설"` 이 **3분 10초** 걸렸다. 두 가지가 겹쳐 있었다 —

    ⑴ **따옴표가 없어 낱말이 AND 로 묶였다.**  통짜 문구가 아니었다.
       「대통령령으로 정하는 주요 부분」  LIKE 3 vs 색인 **3,881** (항은 4 vs 18,629)
       ⇒ 조ㆍ항ㆍ호ㆍ별표 24자리 중 **19자리가 달랐다.** 색인을 쓸 때와 안 쓸 때 답이 달랐다.
    ⑵ **칸을 안 좁혀 열쇠 칸(`짚`)에도 걸렸다.**  `짚` 이 「…법률|제2조」 꼴이라
       **법령 이름이 본문인 척**했다 — 「장애인ㆍ노인」 본문 43건인데 122건.

⇒ 이제 `글 : "…"` 로 물어본다.  무작위 표본 44~81개로 재어 **LIKE 와 어긋남 0**,
  **49~86배**.  `--잣대재기` 가 그것을 상설로 잰다.

⚠⚠ **덤으로 잣대 하나가 뒤집혔다.** 「한 조각이라도 두 자면 색인을 안 쓴다」는
  **너무 넓게 막고 있었다.** 구절 질의는 빈칸까지 삼자에 넣으므로
  「신축이 아닌 기존시설」ㆍ「대지 안의 공지」는 **두 자 조각이 섞여도 정확하다**(108＝108).
  진짜 경계는 **물음 전체가 석 자 미만**일 때다 — 「조경」ㆍ「높이」ㆍ「조례」는 여전히 거짓 0.

⚠⚠ **명령줄에 없는 것이 파이썬에는 있다.** 이 스킬이 스스로 걸어 둔 물음 둘 —
「누가 이 조를 가리켜」ㆍ「별표 보여줘」 — 은 **`찾기.py` 옵션에 없다.**
그것만 보고 「우리 창고엔 그 기능이 없다」로 결론 내리면 안 된다. 앞문은 이렇다 —

```python
import sys; sys.path.insert(0, r'10_Ai', '1_법DB')
import 찾기;  ㅂ = 찾기.열기()

ㅂ.들어옴('건축법 제56조')          # ★ **누가 이 조를 가리키나** (거꾸로)
ㅂ.별표('건축법 시행령')            # ★ **별표 목록** · ㅂ.별표('건축법 시행령', 1) 본문
ㅂ.조키('건축법 제53조의2')         # 가지조 열쇠  ⚠ `찾기.조키(…)` 가 아니다 (모듈엔 없다)
ㅂ.되받는조례('…시행령 제84조')      # 「조례로 정한다」를 되받는 조례
ㅂ.수치('건축법 제56조')            # 그 조에 적힌 수
```

## 축 — **분석하지 않는다. 옮겨 적는다**

> *"분석하지 않고 원문을 그대로 인용 → 신뢰도 높음 / 네가 분석을 하는순간 신뢰도가 떨어짐"*

`법.db` 의 모든 줄에 **`출신`** 이 있다 — `법제처XML`ㆍ`법제처HTML`ㆍ`법제처연계정보`ㆍ
`법제처행정규칙`ㆍ`법제처해석례`ㆍ`지자체지침` **여섯**.
⚠ 「넷(사람 포함)」이라 적혀 있었다 — `사람` 은 법.db 에 **0줄**이고 `규정.db` 에 산다
  (2026-09-08 에 등록부에서 뺐다. 그전에는 검증 ③ 이 매번 「⏸ 안 쓰인 출신 — 사람」을 찍어
  **늘 켜진 빨간불**이 되어 있었다).  값은 `짓기.py` 의 `법db출신` 한 곳에 있다.
**`추론` 은 값으로 두지 않는다.** 못 채우면 NULL, 화면은 「⏸ 아직 안 물었다」.

★★ **「등」이 붙었다고 여는 쪽으로 읽지 않는다 — 조문이 호를 못박았으면 그 호만 센다** (2026-09-21)

우리 글이 「개별 법률이 정한 용도구역(수산자원보호구역ㆍ입지규제최소구역 **등**)」이라 적어
**열린 목록처럼** 보였다. 그래서 대공방어협조구역ㆍ가축사육제한구역ㆍ공장설립제한지역을
들어 「해당있음」으로 닫았다. 그런데 **체크 원본이 「5항 : 1호~5호 · 6항」이라 범위를 못박았고**,
국토계획법 제76조⑤을 펴 보니 **각 호가 닫힌 목록**이었다 — 그 셋은 거기에 없다
(저마다 다른 체크항목이 본다).

⇒ **「등」은 우리 글의 말버릇이지 법의 글자가 아닐 때가 많다.** 세기 전에 **조문을 펴서
  각 호를 읽는다.** 열어 읽으면 도시지역의 웬만한 대지가 다 걸려 **그 상자가 죽는다.**
⚠ 이것은 §4 「짐작하기 전에 원본이 이미 답을 주고 있나 본다」의 법 쪽 얼굴이다.

    2026-08-28  행정규칙 24,124건을 받았다 — **창고 안으로 들어왔다**
    2026-08-31  그런데 `--찾기` 는 여전히 0건이었다. **조ㆍ항ㆍ호ㆍ목 넷만 봤기 때문이다.**
                실제로는 행정규칙조문에 **105건** 있었다 (계약예규 공사계약일반조건 제14조 …)

⇒ **`--두루` 를 쓴다.** 훑는 것은 **열세 갈래**다(2026-09-08) —
  조ㆍ항ㆍ호ㆍ목ㆍ별표ㆍ부칙ㆍ행정규칙조문ㆍ행정규칙절ㆍ행정규칙별표ㆍ옛조ㆍ해석례ㆍ**지침**ㆍ**행정규칙 부칙**.

    2026-09-07 에 둘이 늘었는데 이 줄이 안 따라와 「지침은 안 본다」로 잘못 읽혔다.

```bash
#   드라이브가 안 내려와 있으면 몇 배로 느려진다 — 코드 말고 **동기화부터** 잰다
```

⚠ **`--찾기` 가 0건인 것은 「법령 조문에 없다」는 뜻일 뿐이다.** 그것만 보고
  「그런 규정은 없습니다」라고 하지 않는다. `--두루` 로 다 세고 나서야 「창고 안 어디에도
  없다」고 말할 수 있고, 그때도 **「우리가 안 가졌다」**일 수 있다.  [[못이음_두갈래]]

## ✔ **`--두루` 의 거짓 「없다」는 고쳤다** (2026-09-08)

전에는 갈래를 훑다 **표를 못 읽어도 그 갈래를 0건으로 세고 총계에 넣었다.**

실패했는데 화면은 「모두 **0건** — 창고 안 어디에도 없다」라고 찍었다. **10건 있었다.**

이제 하나라도 못 읽으면 이렇게 낸다 —


**읽는 규칙 — 총계가 `?건` 이면 결론짓지 않는다. 다시 돌린다.**

## ★ 기존 건축물이면 **부칙**을 본다 — 현행 별표에 없는 완화가 부칙으로 온다 (2026-09-11)

「기존건물이라 0.8m 적용이 되지 않나」를 **현행** 편의법 규칙 [별표 1] 에서 찾으면 **없다**
(현행 제6호가목(1)은 0.9m, 단서 없음). 답은 **부칙**에 있었다 —
규칙 부칙 \<제557호\> 제3조 「이 규칙 시행 당시 **이미 설치되어 있는 편의시설**에 관하여는
별표 1 제6호가목(1)… 의 개정규정에도 불구하고 **종전의 규정**에 따른다」 → 종전 판 「0.8미터 이상」.

    ① 부칙은 조 표에 없다 — **`--부칙` 으로 뜬다**(2026-09-11 에 붙였다)
         python 10_Ai/1_법DB/찾기.py --부칙 "<법령명>" --몇 3
       머리에 **경과조치가 어느 부칙에 있나**를 찍고, 두 갈래를 **갈라 센다** —
       「**이미 설치되어 있는**」(기존 건물이 걸리는 갈래) vs 「행정절차 진행 중」(그때 절차 중이던 건물).
       ⚠ 그날 나는 `--help` 만 보고 「옵션이 없다」며 SQL 을 손으로 짰는데 **`법DB.부칙()` 은 앞문에 이미
         있었다** — 아래 「명령줄에 없는 것이 파이썬에는 있다」에 내가 걸린 것이다. **둘 다 본다.**
    ② 「종전의 규정」 원문은 법.db 에 **없다** — 법.db 는 현행 한 벌이다(판본 표에 그 법 0건).
       ⇒ `law-download` 의 `--옛법 "<법령명>" --날 <부칙 시행 전날>` 로 받는다
    ③ 받은 옛 판은 **법.db 밖**(`10_Ai/1_법DB/0_원본/법령_옛판본/`)이라 `채점.py` 가 못 잰다 —
       문답에 실을 때는 근거가 아니라 「곁」에 **XML 경로와 함께** 싣고 「채점 밖」이라 적는다.
       부칙 자체는 근거로 걸 수 있다 — `- Ⓑ [<법령명> 부칙 제3조(제목)](…)` 꼴이면
       채점이 **부칙 표**와 맞댄다.

    ④ ★ **부칙이 부르는 자리 번호는 「부칙 시행일의 판」 번호다** — 현행 번호가 아니다.
       제557호의 「제6호가목(2)」를 현행에서 찾으면 체육시설 1.2m 가 나온다(틀린 자리). 2018-08-10 판에서는
       문 옆 0.6m 활동공간이었고, 2022 개정이 한 칸 끼워 넣어 현행 가목(3)으로 밀렸다.
       ⇒ 판 **셋**을 본다 — 종전(부칙 시행 전날) · 개정(부칙 시행일) · 현행. 둘만 보면 자리를 잘못 짚는다.
    ⑤ 부칙이 묶은 자리가 여럿이면 **하나씩 다** 판다 — 수치가 같은 자리(글귀만 다듬음), 종전엔 **없던**
       자리(개정으로 신설), 번호가 달라 **내용으로** 짝지어야 하는 자리가 섞여 있다(편의법 제557호 열 자리 실측).

⚠ 「현행에 없다」를 「법에 없다」로 옮기지 않는다 — 그건 **현행 본칙만 본 것**이다.

## 「조례로 정한다」는 **거꾸로** 간다

법제처의 `joDelegateOrdinPop` 은 **받는 조례를 특정하지 않는다** — 그 위임은
**지자체마다 조례 하나씩**으로 가기 때문이다. 하나로 정해지는 관계가 아니다.

⇒ 조례가 스스로 「영 제84조제5항에 따라」라고 **밝힌 것을 되받는다**(`--되받기`).
  그건 조례 원문에 적힌 글이지 우리 짐작이 아니다.  [[조례_되받기]]

⚠ 안 나오면 **「없다」가 아니라 「우리가 안 가졌다」**이다 — 조례 **977개**(서울 25개 자치구 전부 + 전국 일부)를
  가졌을 뿐, 전국 자치법규는 훨씬 많다.

## 낱말로 찾기 — **`낱말.db` 가 있으면 0.8초, 없으면 몇 분**

```bash
python 10_Ai/1_법DB/찾기.py --두루 현장대리인        # 다 훑고 센다
python 10_Ai/1_법DB/짓기/낱말색인.py --짓기          # 색인이 없거나 법.db 를 새로 지었으면
python 10_Ai/1_법DB/짓기/낱말색인.py --대장          # 무엇이 색인돼 있나
```

⚠ `짓기.py --짓기` 로 법.db 를 다시 지으면 **낱말.db 가 낡는다.** 다시 짓는다.
⚠⚠ 색인은 **trigram** 이라 **석 자부터**다. 여기 「LIKE 와 같은 것을 잡는다(38＝38)」라고
  적혀 있었는데 그것은 **석 자 낱말 하나로만 잰 것**이었고, 2026-08-31 에 틀린 것으로
  판명나 코드에서 뜯어냈다. **두 자 낱말은 거짓 0건**을 낸다 —
  조경 0/94 · 옥상 0/124 · 대지 0/247 · 일조 0/12 · 높이 0/318 · **조례 0/3,178**.
  ⇒ `찾기.py` 가 **물음 전체가** 석 자 미만이면 앞을 막고 「색인을 안 쓴다」를 찍는다.
    (2026-09-07 정정 — 그전에는 **가장 짧은 조각**을 봤고, 그 탓에 멀쩡한 물음에서도
     색인을 버려 `--두루` 한 번이 **3분 10초**였다.)
    **낱말.db 를 직접 MATCH 로 두드리는 코드를 짜면 그 보호가 없다.**  [[두자낱말_거짓0]]
  `unicode61` 은 「**최대**건폐율」을 못 잡아 안 쓴다.
⚠ `--찾기` 결과가 0건인 것을 **「없다」로 옮기지 않는다.** 그건 법령 조문만 본 것이다.
