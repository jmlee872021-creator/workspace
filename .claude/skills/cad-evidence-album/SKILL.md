## 1 · 차례

```
① 무엇의 근거인가        호실 · 갈래(전기 · 소방 · 설비 …) · 그림첩을 둘 폴더 — 모르면 묻는다
② 생각의 차례를 짓는다    장 목록(--장목록)에서 「밖에서 안으로」 차례를 고른다
                         전기  한전 인입(배치도) → 배전반 단선결선도 → 간선 계통도ㆍ간선 표 → 호실 분전반 결선도 → 분전반 자리(평면) → 호실 안
                         소방  물 : 펌프실 → 송수구 → 층 배관ㆍ일람표 → 호실 안 / 감지 : 계통도 → 호실 안 / 제연 : 풍량 표 → 호실 안 / 피난 : 유도등
                         ★이 차례는 사용자의 의도다 — 한 줄로 보이고 §2 꼴로 여쭌다(「이 차례로 만들까요」) · 한 갈래씩(전기 먼저 → 보신 뒤 소방)
③ 장마다 짚을 글을 찾는다  --글찾기 로 낱말 → 그 글의 자리(도곽 몫 u v) · 표 틀ㆍ범례 같은 블록 속 글까지 나온다
                         낱말 없이 --범위 u0 v0 u1 v1 → 그 범위의 글 전부 · --블록 → 그 범위 블록 이름과 수
④ 차례표(yaml)를 쓴다     단계마다 제목 · 이어짐(앞 장과 잇는 한두 문장) · 그림(장 · 범위 · 표시[머리 · 찾을 · 메모])
⑤ 돌린다                 처음엔 바탕을 그린다(장마다 몇 초 ~ 6분) — 시작 전에 걸릴 시간을 말한다
⑥ 그림을 한 장씩 본다     네모가 글을 다 감싸나 · 범위에 딴 표가 끼었나 · 표 위아래가 잘렸나 · 메모가 그림 높이를 넘나 → 고쳐 다시 돌린다(바탕을 다시 쓰니 몇 초)
                         ★호실 안의 수(헤드ㆍ감지기ㆍ그릴 …)는 앞 검토서의 표와 하나하나 맞대 본다 — 그림첩과 검토서가 다른 수를 말하면 안 된다
                         ★도면 글로 잇지 못한 것(어느 줄이 그 호실인지 · 같은 기호가 두 곳인 까닭)은 메모에 단정해 적지 않고 보고에 따로 댄다
⑦ 낸다                   그림첩 폴더에 · 화면 이름은 자리.산출물이름(차례표의 주소ㆍ이름접두) · 끝나면 탐색기로 화면 html 을 골라 둔다
⑧ 기록                   차례표는 작업 폴더에 둔다(다시 낼 때 그대로) · 새로 드러난 어긋남(도면끼리 다른 글)은 메모로 그림에 남기고 보고에서 먼저 말한다
```

## 5 · ⚠ 함정 — 값을 치르고 얻은 것

- ⚠ **yaml 메모 줄은 작은따옴표로 감싼다** — 「도면 표기 : …」 의 쌍점과 「」 사이 쉼표를 yaml 이 갈래로 읽는다(2026-10-03 처음 판에서 한 줄이 여러 줄로 갈라졌다).
- ⚠ **대지 폴더 경로의 대괄호** — `[문의]` 가 든 경로를 `glob` 무늬에 넣으면 조용히 0개다(뿌리 CLAUDE.md §5) · 도구는 `os.listdir` 로 찾는다.
- ⚠ **표 틀 속 글** — 결선도 표의 「NO.」 같은 글은 표 틀 블록 속에 있어 처음 판에서 못 찾고 멈췄다 → 도구는 블록 속 글까지 장 자료에 넣는다(`--글찾기` 에 「블록 속」 으로 나온다).
- ⚠ **작게 돌려 쓴 글** — 배치도의 「TR PAD」(90° 돌림)는 네모가 점처럼 작았다 → 네모는 그림 높이의 3.5% 보다 작게 치지 않는다.
- ⚠ **같은 글이 여러 곳** — 「LS-P1-8」 이 계통도와 간선 표에 다 있다 → 찾을 글마다 「가까운 자리」(u v)를 준다. 가장 가까운 것을 고른다.
- ⚠ **범위에 딴 표가 끼면** 읽는 눈이 흩어진다 — 배치도 아래 케이블 표를 범위를 좁혀 뺐다.
- ⚠ **범위는 A3 비(가로 : 세로 = √2 : 1)로 넓혀진다** — 세로로 긴 표를 좁은 가로 범위로 적으면 위아래가 잘린다(디퓨져 일람표의 제목과 둘째 네모가 잘렸다) → 가로 범위를 표 높이 × 1.4 만큼 넉넉히.
- ⚠ **멀리 떨어진 두 곳은 한 그림에 넣지 않는다** — 송수구의 범례(도곽 위쪽)와 자리(아래쪽)를 한 범위로 잡았더니 단지 북쪽만 크게 나오고 송수구는 끝에 걸렸다 → 범례 그림 · 자리 그림 둘로.
- ⚠ **범례가 도면 틀 블록 속에 있는 장**(EF-701 · EF-150) — 처음엔 `--글찾기` 에 범례 글이 안 나왔다 → 도구가 도곽 틀 속 글도 장 자료에 넣는다(「블록 속」 으로 나온다 · 메모의 「」 로 인용할 수 있다). 개포동의 호실 안 그림(g20)은 아직 그 글을 못 읽어 메모에 범례가 안 실린다 → 그 단계 이어짐 글에 적었다.
- ⚠ **도곽이 서로 붙어 있는 꾸러미**(EF-701) — 이웃 장 도곽 틀의 넣은 점이 이 장의 가장자리에 걸려, 이웃 범례 글이 이 장 것으로 섞였다(도곽 몫 1.94 자리의 「프리액션 밸브」) → 도구는 이웃 도곽 틀과 장 밖에 놓인 글을 뺀다. `--글찾기` 결과에 몫이 0 ~ 1 을 벗어난 글이 보이면 탈이다.
- ⚠ **메모가 길면** 그림 높이를 넘는다(계통도에 네모 여섯 → 105화소 넘침) → 도구가 판을 아래로 늘려 안 잘리게 하지만, 그림 하나에 네모는 다섯 안쪽이 읽기 좋다. 넘치면 메모를 줄이거나 그림을 둘로 나눈다.
- ⚠ **글이 없는 기호는 블록 이름으로 확인한다** — 계통도의 조작반 옆 밸브 기호에는 글자가 없었다. `--글찾기 --블록 --범위 …` 로 보니 블록 이름이 「P.V」(범례의 프리액션 밸브) 2개였고, 그래서 「일람표에는 1개 ↔ 계통도ㆍ평면도에는 두 벌」 이 드러났다.
- ⚠ **블록 속 안 보이는 것** — 스프링클러 헤드 블록 속에 얼린 레이어의 반지름 2,300 원(설계 수평거리)이 들어 있어, 블록 둘레로 친 네모가 4.6m 짜리가 됐다(수는 13 으로 맞았고 자가검사도 통과한 채였다 — 실물 장에 돌려 그림을 보고서야 드러났다) → 도구는 얼리거나 끈 레이어ㆍ출력 끈 레이어의 것을 글 찾기와 블록 둘레에서 뺀다. ★새 기능은 자가검사만 믿지 말고 실물 장 하나에 돌려 그림을 본다.
- ⚠ 호실 안 기구 그림(개포동은 작업기록의 `g20_주석그림.py --B만`)에서 기구표의 칸 이름 「상자」 가 새로 넣은 칸과 겹쳐 배기 그릴 네모가 사라졌다 — 다른 도구의 표에 칸을 더할 때는 있는 칸 이름부터 본다.

## 6 · ⏸ 아직 안 한 것

- 도구의 `블록` 표시(둘레 안 블록마다 작은 네모와 번호)는 실물 장 ★하나에만 돌려 봤다 — 개포동 소화배관 평면도(MF-360)의 8호 헤드 : 13곳 · 앞 검토의 기구표와 수ㆍ자리가 같다(2026-10-03 마무리 때 · 5절 「블록 속 안 보이는 것」). 전등ㆍ감지기처럼 넣은 점이 기호 가운데가 아닌 블록은 아직 안 돌려 봤다(도구는 넣은 점이 아니라 보이는 것의 둘레로 네모를 친다). 개포동 그림첩의 호실 안 그림은 작업기록의 `g20_주석그림.py --B만` 이 기구표로 그린 것이다(`그림파일` 로 실음). 다른 대지에서 쓸 때 수를 손으로 한 번 세어 맞대 본다.
- 범례가 도면 틀 블록 속에 있는 장(EF-701)의 범례 글을 호실 안 그림 메모에 싣는 것 — 도구는 이제 그 글을 찾지만, 개포동의 호실 안 그림을 그리는 g20 은 아직이다.
- 전기ㆍ소방 말고 다른 갈래(급배수ㆍ환기 …)와 다른 호실은 안 해 봤다 — 차례(1절 ②)부터 사용자와 정한다.
