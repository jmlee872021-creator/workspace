⚠⚠ **걸음 표를 여기 옮겨 적지 않는다** (2026-09-08 에 지웠다). 여기 있던 표는
  **옛 9걸음 번호**였고, 지금 차례와 어긋난 채 남아 있었다 — 「6ㆍ7ㆍ8걸음이 빠진다」는

⚠ 지금 축(법률 DB 먼저)에서 **빠지는 걸음**은 `돌리기.py` 의 `빠진걸음` 에 적혀 있다 —

## ⚠⚠ 법을 새로 받았다면 — **차례를 지킨다**

```
법령받기 → 원문HTML받기 → 링크뽑기 → 링크풀기 → 짓기 → **붙이기** → 맞대보기
        → 낱말색인 → 검증 → 수치 → 오프라인
                            ↑ 여기를 빠뜨리기 쉽다
```

**원문 HTML 을 받아도 링크는 안 생긴다.** `링크뽑기.py --뽑기` 가 HTML 을 읽어
`10_Ai/1_법DB/0_원본/법령HTML/링크/*.json` 을 만들고, `링크풀기` 는 **그 JSON 을 읽는다.**

2026-08-28 에 이 걸음을 빠뜨려 **짓기를 두 번(20분씩) 돌리다 버렸다.** 증상은 조용했다 —
`링크풀기` 가 *"이번에 풀 것 **0개**"* 라고 멀쩡히 답했다. 새 링크가 없어서가 아니라
**읽을 JSON 이 안 만들어져서**였다.

⚠ **`원문HTML받기` 는 `돌리기.py --차례` 에 없다** — 차례는 링크뽑기부터다. 새로 받은 법이 있으면 **먼저 손으로** 돌린다.
  `--받기 --없는것만` 은 새 법만이 아니라 **HTML 이 없는 법령 전부**를 받는다 — 2026-09-15 새 법 15건을 받으려다
  **378개**가 걸렸다(09-07 에 덧붙인 조례가 HTML 없이 들어가 있었다). 받고 나면 링크 수가 새 법 몫보다 많이 는다 — 보고할 때 갈라 센다.
  「본문 아님」 4개는 원래 탈이고(⑴), 법제처 응답 없음(`WinError 10060`)은 `--이름` 으로 한 번 다시 받는다.

**잣대 한 줄** — 이 둘이 같아야 한다.

```bash

python -c "import os;print(len([f for f in os.listdir('10_Ai/1_법DB/0_원본/법령HTML/링크')"
"          if f.endswith('.json') and not f.startswith('_')]))"
# ⚠ 밑줄 파일(`_대장.json`)은 링크가 아니라 **대장**이다. 안 빼면 늘 하나가 더 나와
#   성한 상태에서도 **영영 안 맞는다** (2026-09-05 실측 2300 ↔ 2301).
```

  이 한 줄에 막혀 시작도 못 했다. `os.listdir` 은 같은 일을 **0.04초**에 한다.

## ⚠ 이 프로젝트가 값을 치르고 얻은 것 — 되풀이하지 말 것

**① `INSERT OR REPLACE` 를 쓰지 않는다.**
`<조문단위>` 는 조뿐 아니라 **장ㆍ절 머리글**도 담는데, 머리글이 **다음 조의 번호를
그대로 쓴다.** 「제1장 총칙」과 「제1조(목적)」이 같은 열쇠가 되어 **3,824줄이 조용히
덮여** 사라지고 있었다. ⇒ 머리글은 `법령키|머리{차례}` 로 가르고, **겹치면 시끄럽게
터뜨린다.**  [[조용한실패]]

**② 되돌림 검증은 파서 결함을 못 잡는다.** 재는 쪽도 같은 파서를 쓰기 때문이다.
조례 조 번호가 **100배** 틀려 있던 것(제48조 → 제4800조)이 그래서 안 잡혔다.
⇒ **잣대를 딴 데서 가져온다** — 조 본문이 스스로 적어 둔 「제51조(…」 와 파서가 지은
이름을 맞댄다. **지금 수는 `검증.py --빠르게` 의 ⑤-2 줄에서 본다** —
34,559 는 **분모가 훨씬 작던 옛 판**의 값이다(지금 잣대가 도는 분모는 실제 조 104,215).
수를 여기 박아 두면 곧 낡는다.  [[재는자를-먼저-의심]] · [[채점_분모부터]]

**③ 조 이름은 `조이름()` 한 곳에서만 짓는다.** `'제%s조' % '30의2'` → **「제30의2조」**.
**다섯 번** 재발했고(마지막 2026-09-01) 한때 **다섯 자리 · 8.9만 줄**이었다.
