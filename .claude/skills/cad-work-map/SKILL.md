# 캐드 작업 지도 — 일감 → 하위 스킬 → 넘겨주는 것

> 📄 사용자 (2026-09-17) : *"이 캐드파일 작업은 거대한 규모가 될 수 있기때문에 관리를 잘 해야될꺼같아 ·
>   캐드파일 작업에서 여러 서브 스킬들도 나올텐데 하위 스킬들과의 연계성도 잘 고려해줘야해"*

>   `10_Ai/10_업무매뉴얼/system_도구/기능장뽑기.py` 가 여기서 뽑는다 (2026-10-02 사용자 — *"캐드 작업에 대한 내용도 있을 것 같은데 그것도 정리해줘"*).

## 2 · 역할 나눔 — ★기본은 조언 · 캐드에 그리는 것은 말씀하실 때만

> 📄 사용자 (2026-10-01) : *"캐드작업은 기본적으로 네가 제어하기보다는 정보를 주는 도와주는 방향으로 해주면 돼"* → Q1 ① 캐드 지침에 적는다
>   바탕 지침(뿌리 `CLAUDE.md` §1 「역할 나눔」) — *"'의도'에 기반을 둔 작업은 사람이 · '정보 검토' '정보탐색'은 Ai 가 하는게 효율이 좋다"*
> 📄 사용자 (2026-09-29) : *"캐드상의 자료를 읽지 말고 dxf 저장해놓은 것을 읽고 조언을 위주로 · 궁금한것을 물어보면 dxf 파일을 읽고 대답"* (스킬 `sheet-titleblock` 0절)
> 📄 사용자 (2026-09-17) : *"대지안의 공지부분은 직접 작업하기보다는 텍스트상에서 출력해주면 > 사람이 작업 · 법률관련 내용들도 … 조언 / 가이드 역할"*

**기본 — AI 는 저장본 DXF 를 읽고 조언한다.** 열린 캐드는 건드리지 않는다(사용자가 명령을 쓰는 중에 다리를 부르면 막힌다).
읽기는 `10_Ai/8_캐드/system_도구/03_도면읽기.py --dxf <저장본>` · `02_도곽표.py` · 답마다 「몇 시 저장본을 읽었나」를 댄다(저장 뒤 고친 것은 안 보인다).
고칠 것은 「도곽 N · 칸ㆍ자리 · 지금 글 → 바꿀 글」로 내고 캐드에는 사용자가 넣는다.
★읽은 저장본은 **도곽마다 PDFㆍ그림(PNG)으로도 낸다** — 캐드 없이 `10_Ai/8_캐드/system_도구/11_DXF도곽출력.py` (2026-10-03 사용자 「캐드 제어에서 dxf를 읽고 조언해주는 역할인데 그러면 dxf를 읽고 pdf, 이미지 등을 만들수 있는것까지 될 수 있어서 더욱 효과적」).
AI 가 잘하는 쪽으로 돕는다 — ★처음의 정보 분석(원문ㆍ자료를 찾아 모으기) · ★고친 뒤 일관성 검토(한 곳을 고쳐 다른 도곽ㆍ표ㆍ글과 어긋난 곳ㆍ놓친 곳을 찾기).

| 일 | AI | 사람 |
|---|---|---|
| 도면을 그리고 고치는 일 전부 (기본) | ★저장본을 읽고 조언 — 자료ㆍ원문 · 넣을 글 · 어긋난 곳 | ★캐드에 직접 · 캐드 열기ㆍ저장 |
| 사용자가 **그려 달라고 하신 일** (템플릿 복사 · 지적도 가져오기ㆍ돌리기ㆍ도곽ㆍ자르기 · 면적 · 표제란 · 설계개요 표 · 지구단위계획 지침 표 · 벽ㆍ그리드ㆍ치수 · 면적표) | 그때만 캐드다리로 캐드에 그린다 · ★검토(저장본 DXF · 캐드에 안 닿음)와 캐드 작업(「응」 하시면 다리 한 번)을 나눠 캐드를 붙잡는 시간을 가장 짧게 — 캐드 모듈 4장(2026-10-01 사용자) (용원리 662 지적도ㆍ설계개요 실적 · 설계개요 코드는 스킬 `design-summary` `초안/`) | 기준 변 · 축척 · 이름ㆍ번호 정하기 · 무엇을 실을지 · 저장 |
| 대지안의 공지 · 지구단위계획 문구 · 용도 판단 · 법 근거 | ★원문을 찾아 **복사할 글**로 낸다 · 확인 안 된 것을 따로 적는다 | ★캐드에 직접 넣는다 (선ㆍ지시선ㆍ글) |

⚠ 셋째 줄(대지안의 공지 줄)을 AI 가 캐드에 그려 본 적이 있다(용원리 662 작업03 행 — 공지선 1m + 지시선 셋). 선은 됐지만 지시선 글상자 자리 찾기가 **두 번 실패**했고, 사람이 넣는 편이 빨랐다. 다시 그리자고 하지 않는다.
