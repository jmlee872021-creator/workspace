# 제조사 도면 → Revit 패밀리 파이프라인

> 상위 : `revit-map`
> 앞 : 제조사 DWGㆍDXF ㆍ카탈로그 · `revit-control` 로 붙은 Revit
> 다음 : `revit-modeling` (API 함정)
> 넘기는 것 : Revit 패밀리 .rfa · 검산

**검증** 2026-08-19 ~ 08-31 · 현대엘리베이터 NEX(MRL) 콘크리트 일반형 7인승으로 **한 벌 완주**.
**산출** 돌출 65개 · 재질 9종 · 판정 라벨 24 · 설계 파라미터 엑셀 원장 · 개념 문서.
**전제** 다른 제조사·다른 부재로 그대로 재사용하는 것을 목표로 씀.

> ★ 이 스킬은 **「무엇을 만들었나」가 아니라 「어떤 순서로, 무엇을 남기며 일했나」** 다.
> 값(엘리베이터 치수)은 예시일 뿐이고, 절차와 원칙이 본체다.

# 0. ★★ 시작하기 전에 — 이것부터 확인한다

```
① 지금 어느 단계인가          ① 대표 1벌 / ② 유형 / ③ 확장   (아래 2장)
② 이 패밀리는 제품인가 리그인가  테스트 리그면 실무 적합성을 묻지 않는다
③ 원장이 어디인가             엑셀? 문서? 화면?  ★한 곳이어야 한다
④ ★국면이 A 인가 B 인가       아래
```

## ★ 국면 A / B — 이걸 먼저 가른다

```
A  자율 진행     사용자가 화면을 안 보고 있다   → AI 가 정한다 (레빗 판단 포함). 끝나고 보고
B  같이 만드는 중  사용자가 화면을 보고 있다     → ★갈림길마다 선택창. 한 번에 하나씩
```
⚠ **국면을 안 가르면 둘 다 틀린다** — A 에서 계속 물으면 진도가 안 나가고,
B 에서 혼자 정하면 나중에 뒤집힌다. 애매하면 **B 로 본다.**

그리고 **작업방식이 검증되지 않았으면 코드보다 매뉴얼이 먼저**다
(`revit-modeling` 스킬의 매뉴얼 검색 방침 · `10_Ai/9_Revit/system_가이드/Revit2021_매뉴얼/`).

# 0-2. ★★★ 착수 계약 — 형상에 손대기 전에 못박는 5개

> **폐기된 5세대 중 4세대가 「형상을 다 만든 뒤에 출발점이 뒤집혀서」 죽었다.
> 그리고 5세대 전부 폐기 직전에 flex·전수검산을 통과한 상태였다.**

템플릿·호스트·복제원본은 **나중에 못 바꾼다.** 형상 한 줄 그리기 전에 다섯을 닫는다.

```
① 호스트 · 템플릿      자립인가 벽 기반인가 · 어느 .rft 인가
                     ⚠ 한국어 팩에는 「미터법 일반 모델」이 없다 (영문 팩 Metric Generic Model.rft)
② 2D 인가 3D 인가      도면 표기용인가 형상까지인가. 둘 다면 상세수준으로 가를 것인가
③ 복제 원본           맨바닥인가, 참고 패밀리에서 출발하는가
                     ⚠ 참고에서 출발해도 ★값은 채택하지 않는다 (모양만)
④ CAD 밑그림 처리      ★구속 금지 · 분해 금지 · ImportInstance 형상 접근 금지(즉사)
                     가장 좋은 것은 아예 안 넣는 것 — 좌표는 파이썬이 DXF 에서 읽어 넘긴다
⑤ 분할 단위           패밀리 하나인가 규격별 여러 벌인가
                     ★「여러 벌로 나눠도 된다」는 허락을 미리 받아두면 파라미터가 안 불어난다
```

⇒ 이 다섯을 §2 「사용자 작업방식 ⑥ 선택창」 서식으로 물어 **문서에 기록**한다.
   기록이 없으면 나중에 뒤집혔을 때 무엇이 합의였는지 아무도 모른다.

# 1. 파이프라인 — 7단계

```
0  원본 준비        DWG → DXF · 사람이 발췌            ★사람
1  전수 분해        원본 블록 전부를 무손실 분리          기계
2  부품도 불러오기   Revit 에 부재별 그룹으로 작도        기계
3  부품도 분석       판정 등급 · 출처 대조               기계 + ★사람 채점
4  부재 통합        뷰별로 흩어진 조각을 실물 부재로 묶음   기계
5  설계 데이터       엑셀 원장 → Revit 출력              기계
6  3D 형상          단면 그대로 돌출                    기계
+  개념 문서        ★사용자 질문에서 자란다              대화
```

## 단계 0 · 원본 준비 — ★사람이 한다

```
① CAD 에서 필요한 부분 발췌   ② 치수(DIMENSION) 삭제
③ ★두 판을 다 남긴다        (가) 블록이 살아 있는 판  (나) 분해한 판
```
⚠ **DWG 는 파이썬(ezdxf)이 못 읽는다.** AutoCAD COM 으로 변환한다
(`10_Ai/9_Revit/system_도구/41_DWG를DXF로변환_개선판.ps1`).
⚠⚠ **10번은 쓰지 마라.** 완료 판정을 「크기가 안 변하면」으로 해서 **EOF 없는 절단본**을 만든다
(실측 32.6MB 절단본 → ezdxf 가 못 읽음). 41번이 그 셋을 고친 판이다.
`accoreconsole.exe` 는 **한글판에서 안 된다.**
★ 변환은 **스크래치패드 사본으로만**, 끝나면 `acad.Quit`, 그리고 **사후 보고**한다.

## 단계 1 · 전수 분해 — ★다 뽑는다

> **추출과 채택은 다른 단계다.**
> ```
> 추출 (읽기)   원본에 무엇이 있나        기계적 · 판단 없음 · ★전부
> 채택 (넣기)   그중 무엇을 넣나          ★사람이 고른다
> ```

**「무엇을 넣을까를 AI 가 판단하지 않는다」는 채택의 규칙이지 추출의 규칙이 아니다.**
둘을 붙여 놓으면 **안 뽑힌 것은 존재를 몰라 고를 수조차 없다.**

> 실제 피해 — 원본 78블록 중 32개만 뽑혀 있었고, 빠진 42개 안에
> 2·3·4층·최상층 출입구(개구높이가 다름)와 최상층 평면이 통째로 들어 있었다.
> 그대로 갔으면 **5개층 중 3개층이 320~350mm 틀린 채로** 만들어졌다.

도구: `30_DXF블록별_부품파일.py <원본.dxf> <출력폴더>` — 무손실. DIMENSION·HATCH·ATTRIB 이 산다.
⚠ 무손실이라 **파일마다 HEADER·TABLES·BLOCKS 가 통째로 복사된다** (파일당 ~2.7MB).

## 단계 2 · 부품도 불러오기 — Revit 에 그룹으로

```
CAD 를 Revit 에 ★가져오지 않는다. 좌표는 파이썬이 DXF 에서 읽어 넘긴다
   ⇒ 「밑그림 구속 금지 · 분해 금지 · ImportInstance 형상 접근 금지(즉사)」가
     적용 대상 자체를 잃는다
부재 하나마다 ★트랜잭션을 따로 연다. 실패해도 그 부재만 다친다
그리기 → 즉시 NewGroup 으로 묶는다 (그룹은 패밀리에서 된다. doc.Create 가 막힐 뿐)
```

## 단계 3 · 부품도 분석 — 판정 등급 4단계

```
[검증됨]              독립 자료의 숫자와 대조 성공 (카탈로그 · 다른 도면 · 산술 폐합)
[3자 일치]            우리 형상분석과 외부가 독립적으로 같은 결론. ⚠제조사 문서 직접확인은 아님
[사용자 판단 - 미검증]  설명은 되나 독립 근거 없음
[미확정]              모르거나, 측정과 설명이 충돌한다
```
⚠ 전부 「확정」으로 뭉뚱그리면 **무엇이 아직 근거 없는지 사용자가 알 수 없다.**
★ **판정이 바뀌면 그 자리에서 화면 라벨을 갱신한다.** 문서만 고치고 화면을 두면 갈라진다.

## 단계 4 · 부재 통합 — ★빠지기 쉬운 칸

**부품도는 뷰별로 흩어져 있다.** 카는 평면에도 · 단면에도 · 정상부에도 조각으로 있다.
```
평면      →  X · Y      형상 그대로 (축척이 맞는 장에 한해)
입 · 단면  →  Z          ★형상이 아니라 숫자. 속성(ATTRIB) · 치수 오버라이드
```
⚠ **단면에서 형상을 뜨지 마라.** 비축척 장이 있고 같은 장 안에서도 구간별 배율이 다르다.
⇒ 「단면을 부재별로 가른다」가 아니라 **「Z 숫자를 부재에 배정한다」**가 맞다.

## 단계 5 · 설계 데이터 — ★엑셀이 원장

```
00_설계 파라미터.xlsx   ← ★사람이 고친다. 원장은 여기 하나
     │ python 38_설계파라미터_엑셀원장.py json
_설계파라미터.json      ← 기계용 (Revit 안은 IronPython 이라 openpyxl 을 못 쓴다)
     │ Revit 쪽이 읽어서 그린다
Revit 화면             ← 출력. ★앵커만 읽고 상대좌표로 그린다
```
★ 원장이 엑셀이면 **Revit 표를 지우고 다시 그려도 손실이 0** 이다.
★ 앵커(예: `STEP03` 라벨) 위치를 읽어 상대좌표로 그리면 **사용자가 블록째 옮겨도 따라간다.**

시트 골격 (그대로 복사해 쓸 것):
```
00_읽는법      이 파일이 원장이라는 것 · 고치는 곳 · 반영 방법 · 등급 정의
10_상수        항목 / 지금 박을 값 / 근거 / 등급 / 변수
20_Z밴드       밴드 / Z상단 / Z하단 / 부재 / X·Y값 / Z값 / 등급 / 변수 / ★3D / ★재질
30_Z연속가변    구분 / 부재 / X·Y값 / Z값 / 등급 / 변수 / 3D / 재질
40_미해결      갈래 / 내용
```
★ **「3D」열과 「재질」열**을 넣으면 엑셀 한 장이 곧 모델의 기록이 된다.

## 단계 6 · 3D 형상 — 단면 그대로 돌출

평면 기호선이 **이미 닫힌 단면**이면 그대로 엮어 돌출한다. 치수를 새로 입력하지 않는다.
```
① 그룹의 GeometryCurve 를 ★재구성해 꺼낸다 (Line→CreateBound · Arc→Arc.Create(a,b,mid))
② 끝점을 이어 닫힌 루프로 엮는다 (tol 0.5mm)
③ CurveArray → CurveArrArray → NewExtrusion
```
> 실적 — 카 레일 T자 21세그먼트·균형추 레일 24세그먼트가 **각각 닫힌 루프 하나**로 깨끗이 엮였다.
> 그리고 그 T자 단면이 **평면에서 그대로 도면 기호**가 됐다. 2D 를 따로 그릴 필요가 없었다.

## + 개념 문서 — ★질문에서 자란다

**목차를 AI 가 정하지 않는다. 사용자가 표를 보다 막힌 자리가 곧 목차다.**
한자어는 **글자부터 푼다** — 나열이 아니라 연결이 본체다.
```
글자   한자 + 훈 + 음.  뜻이 여럿이면 ★어느 뜻인지 고르고 왜 그런지 적는다
연결   고른 뜻들을 이어 한 문장으로
정의   그 문장에서 실제 용어 정의로
```
★ **개념이 값의 오류를 잡아낸다** — 실적: 조속기가 폐루프임을 설명하다가
  분류 오류(Z 가변→연속)와 **누락 부재(피트 인장도르래)** 를 동시에 발견했다.

# 2. ★★ 사용자 작업방식 8원칙

이게 이 스킬의 본체다. 절차는 바뀌어도 이건 안 바뀐다.

## ① 대표 1벌 → 유형 → 확장

```
① 대표 1벌   ★하드코딩 · 유형 1 · 치수 파라미터 0.  여기서 구조·치수제어 규격이 생긴다
② 유형       ①의 규격이 선 다음
③ 확장       ②가 선 다음 (인승·규격 변화)
```
> *"파이프라인이 불안정하기 때문이야 … 처음부터 너무 많은 유형을 다 고려하려면
>   패밀리가 너무 복잡해지자나"*

⚠ **표를 만들다 보면 표가 곧 설계인 줄 알고 앞서가게 된다.** 실제로 그렇게 되어
「유형 10종 + 인스턴스 + IF 분기 + 유형 카탈로그」를 권고했다가 바로잡혔다.

## ② 사람이 열어서 고칠 수 있게

```
❌ 파라미터 몇 개로 전부를 구동할 수 있나
✅ 사람이 열어서 고칠 수 있나
```
수식·IF·유형 카탈로그로 다 엮으면 **AI 는 편하고 사람은 못 고친다.**
값이 표에 그냥 적혀 있는 쪽이 수식으로 유도되는 쪽보다 낫다.
★ **「패밀리를 규격별로 따로 만들어도 된다」** — 한 파일에 욱여넣느라 복잡해질 바에는 여러 파일이 낫다.

## ③ 최대반영 후 감산

자료에 있으면 일단 다 넣고 협의해서 뺀다. **「이름을 못 붙였다」는 뺄 사유가 아니다.**

## ④ 부재마다 요구되는 엄밀도가 다르다

> *"중요한 요소가 아니니까 그냥 표현하면 돼. 추정값으로 논리적인 설계기준에서
>   크게 벗어나지만 않으면, 즉 이상하지만 않으면 되는데"*

⚠ 모든 부재에 [검증됨]을 요구하면 표가 무거워지고 진도가 안 나간다.
**원장 대조가 필요한 것과, 상식선이면 되는 것을 먼저 가른다.**

## ⑤ 화면이 곧 진행상황판 · ★배치는 사용자 것

```
❌ 표·라벨을 지우고 다시 그리기 (좌표 하드코딩)
✅ ① 있는 것은 ★내용만 갈아끼운다   ② 새로 그릴 땐 기존 위치를 읽어 그 옆에
   ③ 지워야 하면 ★무엇을 몇 개 지울지 먼저 보고하고 승인받는다
```
사용자는 화면을 **읽기 위해** 정리한다. 매번 초기화하면 결국 화면을 안 보게 된다.
★ 배치 규칙 예 — 모델 왼쪽, 분석물은 **모델 오른쪽에 STEP01/02/03 순으로** 쌓는다.

# 3. 자료 취급 규칙 — 여기서 값이 뒤집힌다

## ⓪ ★출처는 세 겹이고, 각자 주는 것이 다르다

```
카탈로그      「방 크기」를 준다        규격표 · 높이표.  ★부품 위치는 안 준다

```
> 이 경계 덕에 **「18인승이라 이름 붙은 21인승 크기 패밀리」**를 값의 출처로 쓰는 것을 피했다.
> 참고 패밀리는 「BIM 이 무엇을 그리는가」를 알려줄 뿐, 치수는 다른 제품 것이다.

★ 카탈로그를 인용할 때는 **쪽·표 이름·행**까지 적는다. "카탈로그에 있다"만 쓰면 반박에서 죽는다.

## ⓪-2 ★식별 신호의 강도 — 센 것부터 쓴다

```
1  DIMENSION 문자 재지정(오버라이드)   도면이 직접 적은 값. 제일 세다
2  ATTRIB / 표제란 속성               도면이 스스로 붙인 이름
3  블록명                            ⚠참고만. 이름이 정체가 아니다
4  레이어                            ⚠한 레이어에 여러 부재가 섞인다
5  기하 패턴 · 상대 위치               최후 수단. 반드시 다른 신호와 교차
```
★ **이름은 정체가 아니라 위치로 짓는다** — 확신 없으면 `10_미규명 (2580x1410) [*U55]` 처럼
   **크기 + 원블록명 + 미규명 표시**를 파일명에 박아 모르는 것을 드러낸다.
★ **외부 답변(사람·다른 AI·기술자료)도 그대로 채택하지 않는다 — 실측과 대조한다.**
> 실례 — 외부가 「*U38 = 카 프레임 크로스헤드」라 답했는데 폭 2672 가 승강로 1850 보다 넓었다.
> 섞인 블록으로 판정하고 [미확정]으로 내렸다.

## ① 블록명·레이어명·파일명을 믿지 않는다

> `LAD-RAIL-8K` 는 「카 레일」이 아니라 **레일 굵기 8kg/m** 였다. 인승이 커지면 균형추로 내려간다.
> 홀버튼은 전용 블록이 있는데도 그 도면에선 **익명 블록**이었다.

⇒ 블록은 **가르는 단위**로만 쓰고, **무엇인가는 형상·치수·기술자료로** 판정한다.

## ② ★장마다 축척이 다르다

값을 쓰기 전에 **반드시** `DIMENSION.get_measurement()`(그린 길이) 와 표기값을 비교한다.
> 실측 — 같은 도면집에서 평면·개구부는 1:1, 단면도는 **구간별 배율 0.470~0.818**,
> 상세도는 1.22/1.45/1.94. 표제란에는 전부 `N.S`(축척없음) 라 적혀 있었다.

## ③ ★치수 문자를 지우고 값은 ATTRIB 으로 찍는 도면이 있다

`dim.dxf.text` 가 `<>` 인지 **공백**인지부터 본다. 공백이면 **ATTRIB 전수회수가 유일한 길**이다.
그리고 **회수한 숫자를 더해봐라(산술 폐합).** 회수만 하고 안 더하면 절반이 남는다.
> 실적 — 속성 22개를 더해보니 두 사슬이 정확히 폐합하면서 「정체 미상」 7개가 한꺼번에 풀렸다.

## ④ ★카탈로그는 제품별로 표가 다르다 — 오염 사고

> 우리 원장의 「표준 3800 · +350 · 주8 · 90→4250」이 **전부 다른 제품(뉴와이저) 표**의 값이었다.
> 두 제품이 한 행에서 우연히 같아 「일치」로 보였고, 다음 행에서 갈라지자
> **「도면이 카탈로그와 안 맞는다」는 잘못된 결론**이 나왔다.

⇒ 카탈로그를 인용할 때는 **쪽·표 이름·행**까지 적는다. "카탈로그에 있다"만 쓰면 반박에서 죽는다.
⇒ **텍스트 추출본은 표가 깨진다.** 표가 중요하면 PDF 원본 쪽을 그림으로 읽는다.

## ⑤ 프로젝트 조건을 제품 상수로 쓰지 않는다

> 층고 4000/2600×3/4150 · 5개층은 **그 도면이 예시로 든 프로젝트 조건**이었다.
> 판본마다 다르고, 최상층 층고는 그냥 MIN OH 를 옮겨 적은 것이었다.

⇒ 원장에 **[예시조건]** 등급을 따로 둔다.

# 4-2. ★★ 검증과 완성 판정 — 「통과」와 「완성」은 다르다

```
★ 검산 기준선은 언제나 ★원본 도면이다.  우리 좌표표 ↔ 우리 패밀리 대조는 검산이 아니다

★ 확인 그림은 생성시각 ≥ .rfa 저장시각 일 때만 유효. 아니면 _폐기_YYMMDD/ 로 내린다
```

**세 겹 검산을 따로 건다** — 하나가 통과해도 나머지가 떨어질 수 있다.
```
① 골격 flex    기준면이 파라미터를 따라오나
② 유형 전수    값 기입 후 원장과 대조

```

⚠ **타임아웃을 「덩어리 줄이기」로 처방하지 마라.** 사고 33건 중 순수 크기 초과는 **1건**.
