# 세움터 접수 — 조언 → 사람이 넣는다 → 검토

> 상위 : `seumter-map`
> 앞 : 사용자의 민원 이름 · 세움터 창 (`system_도구/01_세움터창.py --열기`)
> 다음 : (사람이 제출한다)
> 넘기는 것 : 준비 도면ㆍ서류 목록 · 칸별 넣을 내용 · 검토 결과 · `10_Ai/13_세움터접수/접수유형/<민원 이름>.md`

> 📄 사용자 (2026-09-17) : *"웹페이지를 보면서 어떤 내용을 넣어야 하는지 등을 조언해줄수 있으면 좋을것 같아"* · *"나중에 접수 유형별로 분석된 자료들이 있으면 해당자료를 바탕으로 업무를 진행하면 되니까"*
> 정한 것 : Q1 ① 조언 + 검토 (입력은 사람) · Q5 ① 창고 `10_Ai/13_세움터접수` · Q6 ① 이 스킬

**이 스킬은 얇게 둔다.** 절차ㆍ자리ㆍ⏸ 는 [`10_Ai/13_세움터접수/쓰는법.md`](../../../10_Ai/13_세움터접수/쓰는법.md) 에 있다 — 여기에 사본을 두지 않는다.

## 틀리기 쉬운 자리

- ★**메뉴는 법의 위임 고리로 고른다** — 말에 「용도변경」이 들어가도 허가 메뉴가 아닐 수 있다 (2026-09-17 수서동 725 · Q10 ①).
  같은 시설군 안 용도변경(건축법 제19조제3항 기재내용 변경)은 `찾기.py --조 "건축법 제19조"` 의 [위임] 고리가 **건축물대장 규칙 제18조**로 가고,
  세움터 메뉴는 「건축·대수선·용도변경허가」가 아니라 **건축물대장 민원 › 건축물표시(변경/정정)신청**이다. 서식 번호로 맞대 본다.
- 법 원문은 스킬 `law-lookup`. 서식의 제출서류 칸과 조문의 첨부서류를 **둘 다** 본다(2026-09-17 표시변경 — 조문 · 별지 제15호서식이 같은 말을 한다).
- 매뉴얼 그림은 작다 — 칸 이름은 **크게 잘라(300dpi) 읽고** 옮긴다. 흐린 그림에서 짐작하지 않는다.
- 사용자 크롬은 끄지 않는다 — 따로 프로필로 띄운다(쓰는법 「세움터 창 열기」).
