# 건축도서 작성메뉴얼 · 건축분야 — 도서를 그리는 순서 13걸음

> 상위 : `law-map`
> 앞 : 사용자가 정한 걸음 차례 + 원본 PDF(「표준 도면 작성 매뉴얼」 서울시건축사회 2025.09 · 35쪽)
> 다음 : 사용자가 매뉴얼 서버 화면에서 읽는다
> 넘기는 것 : `10_Ai/10_업무매뉴얼/3_건축도서_작성메뉴얼/건축분야/*.html` (차례 1 + 걸음 13)

> ⚠ **2026-09-21 사용자 Q13 ① — 이 권은 업무 매뉴얼 왼쪽 메뉴에서 뺐다** (*"불필요한 메뉴일것 같아"*) · 그 자리에 「법률검토」 권.
>   파일(장 15 · 정본 · 그림 · 원본)은 `3_건축도서_작성메뉴얼/` 에 그대로 — 「사무소 자료 › 사무소 운영 매뉴얼」 이 이 폴더를 22곳 가리키고, 같은 정본에서 `걸음장.py` 로 뽑힌다.
>   `걸음장.py --뽑기` 는 목록.js 에 「건축분야」 칸이 없으면 그 목록을 건너뛰고 사무소 운영 매뉴얼 줄만 고친다 · `인용.py` 는 이 폴더를 「메뉴에서 뺀 권」으로 목록 잣대 밖에 둔다.
>   ⇒ 「건축도서 작성메뉴얼 다시 살리자」 가 오기 전에는 이 권의 장을 새로 짓거나 메뉴에 올리지 않는다.

**이 한 장이 차례다.** 쓰는법(1,441줄)은 그 권 절이 걸릴 때만 연다.

★ **이 세션이 맡은 일감 파일** — `00_길잡이/이어서/매뉴얼_그밖.md`

> 사용자 (2026-09-19) — *"건축분야는 대지분석 - 규모검토(매스검토) - 세부 법령검토 - 설계개요 작성 -
> 배치도 작성 - … 필요도면 작성 순 · 계약 등은 도서 작성 순서와 별개니까 제외 ·
> **추가 자료가 들어오면 update 하는 과정**"*

             python …/걸음장.py --자가검사     17가지

## 2 · 걸음 장의 꼴 — **셋뿐이다**

```
1 개요       풀이 · 제안(⏸)
2 일의 순서   매뉴얼 원문절 — 절 제목 + 쪽그림 + 쪽 글자 + 원본 보기 (없으면 「아직 없다」 한 줄)
3 노트       도구 · 우리 자료 · 사례 ①②③ · ⏸ 모름 · 실무 메모   ← **있는 갈래만**
꼬리         이력 · 지적사항(접힘)
```

> 2026-09-19 사용자 — *"의미 없는 내용이 많다 · 분류는 이 정도로만 · 세부 소제목과 내용 혹은
> 세부 분류는 **해당 작업을 하면서 수정해나가는 방향**"*
> ⇒ 일곱 부문이 **빈 갈래마다 자리채움 글**을 찍던 것을 걷어냈다. **빈 칸을 만들지 않는다.**

⚠ **머리 표 이름은 「앞 업무 · 이 업무 · 다음 업무」다.** 화면(`댓글.js` 머리표묶기)이
  그 이름만 알아보고 「◂ 앞 업무 · 다음 업무 ▸」 칩으로 꾸민다 —
  「앞 걸음 / 이 걸음 / 다음 걸음」으로 뽑으면 **그냥 표 3줄**로 나온다. 자가검사가 이름을 잰다.

## 3 · 함정

- ★**「절 → 걸음」 짝은 내 제안이다** (정본 「정한것」 넷째 줄). 5-7 레벨 표시는 입면도 장에
  덩이가 갔다(단면도엔 고리). **틀리면** 정본의 그 걸음 `원문절` 줄을 옮기고 `--뽑기`.
  ⇒ 사용자가 짚기 전에는 **확정이 아니다** — 보고할 때 그렇게 말한다.
- **같은 쪽에 절이 둘**(1-1ㆍ1-2 가 3쪽)이면 쪽그림이 절마다 한 번씩 나온다 —
  합칠지는 사용자가 보고 정한다(⏸).
- ★**원본 매뉴얼에는 설계 진행 순서가 없다** (3-4 도면 작성 절차 · 6-1 CAD 작성 순서뿐).
  차례 장 「3. 원본 매뉴얼이 적은 순서」에 따로 둔다 — **걸음의 축은 사용자가 정한 것**이다.
  원본에 없는 것을 원본인 양 싣지 않는다.
- **장을 손으로 고치지 않는다.** 고치면 `--검사` 의 「장 낡음(지문)」에 걸린다.
  정본 yaml 을 고치고 다시 뽑는다.
