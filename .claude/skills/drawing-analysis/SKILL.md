## 1 · 모든 작업에 공통인 규칙

### 원본과 근거

- **TIF 가 기준이다.** 도면 분류ㆍ목록ㆍ위치는 TIF 로만 정한다. TIF 에서 흐린 치수ㆍ글자는 **사용자에게 사진 확인을 부탁**한다.
  흐린 자리가 선을 따라 그을 만큼 넓으면 — 사용자가 구름을 그리고 AI 가 그 자리 사진을 원도에 맞춰 펴서 나란히 붙인다(2절 「작업09」 · 2026-09-22 Q1 ①)
  > *"jpg는 사용자가 찍은 사진이라서 분류가 정확하지 않을수 있어. TIF를 기준으로 하고 해당 부분 치수나 내용이 부정확하면 사진으로 확인해달라고 요청하면 돼"*
- **근거 없는 값은 쓰지 않는다.** 원도에서 직접 읽은 값은 도면번호ㆍ크롭이 곧 출처다.
  v2 ㆍ옛 DB 에서 가져온 값은 쓰기 **전에** 그 근거(원도 크롭ㆍ검산)를 연다. 못 열면 「근거 미확인」.
  > *"원도면에서 가져오던, 다른도면에서 가져오건 검산 / 증명 의 근거가 없으면 함부로 쓰면 안되는거야"*
- 값은 **원래 해상도 크롭**에서 읽는다. 줄여 본 개관은 「어디에 있나」를 찾는 데만 쓴다.
- ★**모양은 지금 그리는 판의 원도대로** — 구조평면이면 구조평면 원도, 건축 평면이면 건축 평면 원도. 다른 도면(일람표ㆍ다른 층ㆍ건축)의 모양을 옮겨 오지 않는다 (2026-09-18 Q10 ① · 작업08 ⑦→⑧)
  ★단 ★「그 판이 무엇을 보는 판인가」가 먼저다 — 1층 구조평면도는 ★지하1층 천장을 보는 판이라 그 밑의 기둥은 지하1층 SRC 기둥이다 → H형강 + ★SRC 800 네모 (2026-09-21 사용자 · Q10 ① 을 바꿈 · 작업09)

### 검산판 — 사용자가 O/X 하는 꼴

칸마다 이 다섯을 붙인다.

```
⑴ 주장 (읽은 값)      ⑵ 출처 (도면번호 · 크롭 파일)
⑶ 판정 (직접 읽음 · 합으로 · 도면끼리 다름 · 추정)
⑷ 원도 크롭 + 그 글자 둘레 빨간 구름 (표시01_빨강)
⑸ 「확인 : 」 빈칸
```

- **답을 안 단 「확인 :」은 동의**다. 답을 적었으면 제가 읽어 해석하고 표(csv)와 캐드 글에 반영한다.
- 도면끼리 다르면 **두 도면 크롭을 나란히** 넣는다 (보기 : 그리드 0─1 간격 · S-013 과 S-003).
- 사용자가 정할 것은 캐드에 **빨간 구름 + 할 일 글상자**로 묻는다. 채팅에는 숫자를 나열하지 않는다.
- 동그라미를 쳐 두면 사용자가 캐드에서 확인한다 — 지운 것 0 · 새로 그린 것 0 이면 동의.

### 행과 단계 — 캐드에 쌓는 꼴 (정본 `기본요소.yaml` 의 `행` · `행제목` · `행개요` · `단계쌓기`)

★**처음 하는 작업은 필수 확인점마다 단계를 나눠 중간 결과물을 캐드에 남긴다** (2026-09-19 사용자).
> *"지금 작업은 처음 하는 작업이기에 파이프라인에 대한 검토가 되면서 진행해야 하니까 중간생성물을 만들면서 진행하자
>  — 토큰 절약을 할 수 없는 요건이지만, 토큰보다도 사용자의 확인이 비교할수 없을만큼 중요한거야"*

파이프라인이 아직 없는 작업은 AI 의 읽기ㆍ판정이 맞는지 사용자가 단계마다 가려야 한다. 토큰 절약 < 사용자 확인.
★단계는 ★작업의 종류로 나눈다 — 「선 읽기」ㆍ「부호 읽기」ㆍ「편심 읽기」처럼. 판마다 평면 ★전체를 다룬다.
  구역ㆍ범위로 나누지 않는다 (2026-09-19 사용자 — 작업09 에서 편 그림을 9구역으로 나눴다가 지적받았다.
  *"구역으로 나눠서 확인하는게 아니라 작업의 종류별로 하나씩 확인을 하는거지"*).
  크롭을 구역으로 자르는 것은 AI 내부 처리일 뿐, 확인점ㆍ단계가 아니다.
  다만 한 단계가 너무 커서 샘플이 필요하다고 판단되면 ★그 단계 안에서 「샘플 → 사용자 확인 → 전체」로 간다
  (2026-09-19 사용자 — *"A → B → C → D 샘플 → D 전체 → E 이런식의 흐름이어도 상관없어"*).

```
행      작업 하나 = 행 하나.  윗 행 아래로 내려 ★왼끝부터.  앞 행의 기준 요소(그리드 등)는 복사해 가져간다
제목    행 맨 왼쪽 「작업NN) 이름」 · 문자03_제목 · 높이 5,000 · x −52,171
개요    제목 아래 · 이름 — 뜻 한 문장 / 핵심 절차 ①②③ (누가) / 이번 결과 수 / 「다음에 요청할 때」 한 줄
단계    행 안에서 단계마다 ★오른쪽으로 복사해 새로 쌓는다.  앞 단계는 그대로 둔다
설명    단계 블록 위 글상자 (문자02_주기 · 높이 900) —
          첫 줄 = 이 블록이 무엇인가(결과) · 둘째 = 왜 · 무엇을 확인했나
          [AI] 한 일 · [사용자] 한 일 · [AI 검산] 수
          ✘ 진행 지시(「오른쪽에 두라고 했다」 · 선택지 번호)는 쓰지 않는다
```

> *"작업 1부터, 해당작업들을 어떻게 했는지 핵심 내용을 정리해서 개요처럼 적어놔야 나중에 다시 그 작업을 수행하려고 할때 … 너한테 설명할수 있는 일종의 프롬프트가 되는거거든"*
> *"다른사람이 다시 내용을 읽거나 다음에 다 잊어버렸다가 다시 내용만 봤을때, 작업내용의 핵심이 드러나있게"*

- 글을 늘리면 **그 아래 그림ㆍ구름을 늘어난 만큼 함께 내린다.** 그린 뒤 「글상자와 겹친 그림 0」으로 잰다.
- 그리기 전에 **자리가 비었는지 훑어 센다** (비어 있지 않으면 멈춘다).
- 치수 글자는 **늘 가운데**. 겹쳐도 AI 가 옆으로 빼지 않는다 — 옮기는 것은 사용자.

## 3 · 함정 — 값을 치르고 얻은 것

- **답은 한국어로.** 이 작업 중 영어로 두 번 답해 *"한글로 설명해"* 를 들었다.
- **캐드가 바쁘면 COM 이 거절한다** (「피호출자가 호출을 거부」) — 호출마다 짧게 쉬며 다시 부르는 감싸개를 쓴다.
- **캐드에 올린 그림 파일은 잠긴다** — 같은 이름으로 다시 저장할 수 없다. 고칠 그림은 새 이름으로 저장해 바꿔 끼운다.
- **json 은 utf-8 로 쓴다** — 인코딩 없이 쓰면 cp949 로 저장돼 다음에 못 읽는다.
- **손잡이 기록의 「뜻」은 ★그린 차례대로 적는다** — `그리기` 에 그림→선→글 로 묶어 넘기면서 뜻을 구름마다 섞어 적었더니 이름표가 어긋났다(2026-09-22 20번 · 잣대 「구름선이 그림 안」 0/3 으로 잡힘). 기록 뒤에 ★종류(RasterImage/Polyline)로 한 번 맞대 본다
- **`cv2.imread`ㆍ`cv2.imwrite` 는 한글 경로를 ★조용히 못 한다** — 읽기는 None, 쓰기는 에러 없이 파일이 안 생긴다(2026-09-22). 그림 읽고 쓰기는 PIL 로 하고 cv2 는 셈에만 쓴다.
- **PDF 에서 그림을 뽑을 때는 그 쪽의 그림 변환(돌림)까지 본다** (2026-10-05 안국동 52-5 현황도 · 사용자 「이미지가 180도 회전해야될꺼같아」) — 스캔 JPEG 가 거꾸로 저장되고 PDF 가 변환 (-a, -d) 로 돌려 보였다. 원본 바이트만 뽑아 캐드에 올리면 거꾸로 선다 ⇒ `page.get_image_info()` 의 transform 부호를 보고 돌려 저장한다 (음수 둘 = 180°)
