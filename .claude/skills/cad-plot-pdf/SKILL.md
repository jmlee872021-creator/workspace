# PDF 출력 — 도곽을 한 파일로

> 상위 : `cad-work-map`
> 앞 : 표제란을 채운 캐드 파일 — `sheet-titleblock`
> 다음 : — (끝)
> 넘기는 것 : `<도면이름>_년월일_시분초.pdf` 한 파일 · 도곽 N · PDF N쪽

> **2026-09-11 에 사용자와 협의해 지었다.** 시트 템플릿 16쪽·개포동 도서 11쪽,
> 둘 다 **어긋난 것 0건**으로 마쳤다.

★**PDF 가 아니라 도곽마다 DWG(2010)** 가 필요하면 — `python 10_Ai/8_캐드/system_도구/08_도곽별DWG.py --문서 "<도면>"` (세움터 접수용 · 2026-09-17 · 수서동 725 26/26)
★**낱장 DXF 접수도서** — 좌측하단 (0,0) 맞춤 → DXF 저장 → DWG 2010 이 반드시 들어간다 (2026-10-06 · 캐드 쓰는법 「DXF 파일 → DWG」)

★**캐드 없이 — DXF 저장본에서 도곽마다 PDFㆍ그림(PNG)** (2026-10-03 사용자 「dxf 파일에서 pdf를 바로 만들수는 없는거지?」 → 「바로 뽑는걸로 하자」 · 「이미지(png)로 만드는 기능도」)
```bash
cd "G:/내 드라이브/Jakin_workspace/10_Ai/8_캐드/system_도구"
python 11_DXF도곽출력.py --dxf "<파일.dxf>" --조회                         # 도곽만 찾아 표로 (번호ㆍ도면명ㆍ축척 · 안 낸다)
python 11_DXF도곽출력.py --폴더 "<DXF 폴더>" --낼 "<낼 폴더>"              # 도곽마다 PDF (번호_도면명.pdf) + 목록.html
python 11_DXF도곽출력.py --폴더 "<DXF 폴더>" --낼 "<낼 폴더>" --꼴 둘 --dpi 200   # PDF 와 PNG
python 11_DXF도곽출력.py … --있으면건너뜀                                    # 끊긴 뒤 이어 뽑기
python 11_DXF도곽출력.py --자가검사                                          # 19가지 · 한글ㆍ가림막ㆍ출력 끈 레이어ㆍ촘촘한 무늬를 깨뜨려 본다
```
- 도곽은 ★블록 이름(FORM ㆍ 폼 ㆍ 도곽 ㆍ TITLE)으로 찾는다 — 남의 도면은 도곽 레이어가 파일마다 다르다. 없으면 사무소 도곽 레이어 `도곽01_인쇄용경계선`.
- ★한글 — 캐드 전용 글꼴(SHX)ㆍ없는 글꼴 이름이면 한글이 □ 가 된다 → 그릴 때만 맑은 고딕으로 바꾼다(파일은 안 고친다). 그래서 글꼴의 모양ㆍ폭과 선 굵기(CTB)는 캐드로 뽑은 것과 다르다 — 원본 그대로가 필요하면 위의 캐드 길.
- ★가림막(WIPEOUT)은 흰색 — 처음엔 「선은 모두 검정」 이 가림막까지 검게 칠해 배치도에 검은 네모ㆍ띠가 났다(2026-10-03) · 출력 끈 레이어ㆍDefpoints 는 뺀다 · 둘 다 자가검사가 깨뜨려 본다(16가지).
- ★촘촘한 무늬 — 종이 위 0.1mm 보다 촘촘한 해치 무늬는 면 하나로 그린다 · 해치 하나에 10초를 넘기면 끊는다. 이것이 없을 때 펌프실 평면도 한 장(J106)이 1시간 반을 넘겼다(무늬 간격 종이 위 0.007mm) → 넣은 뒤 6초.
- 끊기면 `--있으면건너뜀` 으로 이어 뽑는다(이미 낸 장은 그대로 · 목록에는 넣는다). 장 수가 많으면 뒤에서 돌리고 시작 전에 시간을 말한다.
- ⚠ 낸 뒤 ★한 장은 그림으로 찍어 눈으로 본다 — 해치ㆍ가림막ㆍ채움이 많은 장(배치도ㆍ조경)에서 다른 탈이 날 수 있다.
- 실적 — 개포동 1280 준공 DXF 여섯 · 도곽 39 / 39 · 분석 때 다른 길로 지은 도곽표와 맞대 어긋남 0 · 단선결선도는 장당 6 ~ 11초, 단지 배치도(해치가 많다)는 장당 4분 넘게.

**상세는 [`10_Ai/8_캐드/쓰는법.md`](../../../10_Ai/8_캐드/쓰는법.md) 에 있다.** 여기는 **언제 무엇을 부르나**만이다.

```

② 어느 도면인가                            →  ★반드시 묻는다.  --문서 없이는 도구가 멈춘다
③ 돌린다                                  →  아래 한 줄
④ 수를 찍어 보인다                          →  「도곽 N개 · 뽑은 것 N장 · PDF N쪽 · 어긋난 것 N건」
                                            ★맞는지는 사용자가 PDF 를 열어 본다
```

## 걸리는 시간 (실측)

```
도곽 찾기  ★0.3초 (엔티티 수에 거의 안 붙잡힌다)          플롯  장당 약 1초
```
★ **2026-09-13 부터 훑기가 안 비싸다** — `00_캐드다리.py`(C#)가 캐드 **안에서** 돌아
한 번에 퍼온다. 전에는 COM 으로 2.5만 엔티티에 63~75초였다 (★28배).
```
표가 없거나 낡으면  02 가 스스로 훑어 표를 짓는다 — ★0.3초라 겁내지 않는다
--훑기             표를 안 쓰고 새로 훑는다 — ★도곽을 더했는데 엔티티 수가 그대로일 때
--COM              옛 COM 길로 (다리와 맞대 볼 때만 · 28배 느리다)
```
★ **이제 오래 걸리는 것은 훑기가 아니라 ★플롯이다** — 장당 1초 x 장수. 26장이면 약 55초.
  그 쉼은 일부러 둔 것이다(없애면 한 장씩 빠진다). 시작 전에 몇 장인지 말한다.

## ⚠ 반드시 지킬 것

```
① ★대상 파일을 묻는다.  「엔티티가 제일 많은 것」 같은 짐작을 하지 않는다
② ★한 번 세고 넘어가지 않는다.  수가 이상하면 다른 방법으로 한 번 더 센다
   (SelectionSet 필터는 같은 것을 ★3 · 8 · 16 으로 셌다.  에러는 안 났다)
③ ★도곽 크기 검산 — 폭 / (높이/297) 가 ★420 인가.  가로세로 ★1.414 가 정상
   1.416 이면 폭이 0.5mm 넓어 ★0.12% 작게 찍힌다 (841 로 재면 거꾸로 판정한다)
④ ★쪽 크기가 신호다.  2KB 짜리 쪽은 ★빈 도곽이다 (팔레트 견본 등)
⑤ ★캐드가 바쁘면 조용히 0 을 준다.  CMDACTIVE 로 먼저 재고, 그래도 막히면 ★캐드를 껐다 켠다
```
